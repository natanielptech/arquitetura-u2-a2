# Glossário

**Unidade 2 · Aula 2 — Prof. Nataniel Paiva**

| Termo | Significado |
|---|---|
| **Aplicabilidade** | Condições em que um padrão ajuda a resolver um problema. |
| **Code smell** | Sinal de que uma estrutura pode merecer investigação; não é prova de que um padrão é necessário. |
| **Consequências** | Vantagens e custos que acompanham a aplicação de um padrão. |
| **DIP** | Dependency Inversion Principle: módulos de alto nível dependem de abstrações, não de detalhes concretos. |
| **Gang of Four (GoF)** | Gamma, Helm, Johnson e Vlissides, autores do catálogo de 23 padrões publicado em 1994. |
| **OCP** | Open/Closed Principle: aberto para extensão e fechado para modificação. |
| **Over-engineering** | Complexidade ou abstrações sem benefício proporcional ao problema. |
| **Padrão de projeto** | Estrutura de colaboração reutilizável para um problema recorrente em determinado contexto. |
| **SOLID** | Conjunto de cinco princípios para orientar projeto orientado a objetos. |
| **ISP** | Interface Segregation Principle: clientes não devem depender de operações que não usam. |
